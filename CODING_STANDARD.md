# Стандарт кодування проєкту TaxiDispatch

## 1. Загальні положення
Цей документ фіксує єдині правила написання коду для проєкту TaxiDispatch. Стандарт економить час на читання коду та мінімізує кількість стилістичних помилок. Будь-який код у репозиторії має відповідати цим правилам.

## 2. Іменування
| Сутність | Конвенція | Приклад | Антиприклад |
| :--- | :--- | :--- | :--- |
| Клас, запис | PascalCase, іменник | `RouteSegment` | `routeSegment` |
| Інтерфейс | I + PascalCase | `IOrderRepository` | `OrderRepository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calc_total` |
| Властивість | PascalCase, іменник | `DistanceKm` | `distance` |
| Приватне поле | _ + camelCase | `_segments` | `m_Segments` |
| Локальна змінна | camelCase | `totalAmount` | `ta` |
| Константа | PascalCase | `MaxCapacity` | `MAX_CAPACITY` |
| Перелічення | PascalCase однина | `OrderStatus` | `OrderStatuses` |

## 3. Форматування
1. **Відступ:** рівно 4 пробіли. Використання табуляції суворо заборонено.
2. **Довжина рядка:** не більше ніж 100 символів.
3. **Фігурні дужки:** стиль Allman (відкривна дужка на новому рядку). Вони обов’язкові навіть для однієї інструкції в тілі `if`.
4. **Порожні рядки:** між членами класу (властивостями, методами) має бути рівно один порожній рядок.
5. **Директиви using:** розміщуються на початку файлу; системні простори імен (`System.*`) ідуть першими, невживані видаляються.
6. **Простір імен:** використовується синтаксис файлового рівня (`namespace TaxiDispatch.Core.Domain;`).

## 4. Коментарі та документація
Коментарі мають пояснювати «чому» ухвалено рішення, а не «що» робить код.
```csharp
// погано: коментар переказує код
// додаємо новий відрізок до замовлення
_segments.Add(segment);

// добре: коментар пояснює неочевидну бізнес-логіку
// Базова ціна зафіксована на момент створення замовлення,
