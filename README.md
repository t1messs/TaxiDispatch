# TaxiDispatch

![CI](https://github.com/t1messs/TaxiDispatch/actions/workflows/ci.yml/badge.svg)

Навчальний проєкт з дисципліни «Конструювання програмного забезпечення».
Варіант № 13: приймання й розподіл замовлень таксі.

## Склад рішення
- `TaxiDispatch.Core` — логіка предметної області (бібліотека класів): домен, сервіс,
  політики ціни, винятки `Errors/DomainRuleException` і тип `Errors/Result`.
- `TaxiDispatch.App` — консольний застосунок: введення, барикада `Input/RouteSegmentParser`,
  журнал, файли звіту та аудиту.
- `TaxiDispatch.Tests` — модульні тести (xUnit).

## Вимоги
.NET SDK 10.0 або новіший, Git.

## Складання, тести та запуск
```bash
dotnet build
dotnet test
dotnet run --project TaxiDispatch.App
```
Застосунок запитує відрізки маршруту (адреса, дистанція, ціна за кілометр);
щоб завершити введення, введіть «готово» замість адреси. Дробові числа — з комою
(«3,5»), крапку теж прийнято.

## Обробка помилок
Класифікацію помилок і стратегії реакції наведено в `docs/errors.md`.
- Помилки введення — `Result`: застосунок пояснює помилку й повторює запит.
- Порушення правил предметної області — `DomainRuleException` з ідентифікатором правила.
- Помилки програміста — стандартні винятки аргументів, «падати швидко».
- Збої файлів — перехоплюються лише у верхньому обробнику `Program.cs`.

Коди завершення: 0 — успіх, 1 — порушено правило, 2 — непередбачений збій,
3 — збій файлової системи.

## Журнали та файли
- Журнал роботи виводиться в консоль (рівні Debug–Critical, область `Order:{OrderId}`).
- `audit.log` — журнал аудиту операцій, `report.csv` — звіт; обидва створюються під час
  запуску й до репозиторію не потрапляють (`.gitignore`).

## Стандарт кодування
Правила описано у файлі CODING_STANDARD.md і закріплено в .editorconfig.
