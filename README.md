# TaxiDispatch

![CI](https://github.com/t1messs/TaxiDispatch/actions/workflows/ci.yml/badge.svg)

Консольний застосунок диспетчера служби таксі: приймає замовлення, добирає найближчого
вільного водія, веде поїздку станами, рахує вартість за відстанню й будує звіт за зміну.

## Автор і дисципліна

Варіант № 13 (TaxiDispatch), Польщенко Нікіта, група 472. Дисципліна «Конструювання
програмного забезпечення», самостійна робота № 3.

## Швидкий старт

Потрібні Git і .NET SDK 10.0 або новіший. Команди виконуються з кореня репозиторію.

```bash
git clone https://github.com/t1messs/TaxiDispatch.git && cd TaxiDispatch
dotnet build
dotnet run --project src/TaxiDispatch.App
```

## Структура рішення

| Проєкт | Призначення |
|---|---|
| `src/TaxiDispatch.Domain` | правила предметної області: тарифи, добір водія, стани замовлення; не залежить ні від чого |
| `src/TaxiDispatch.Application` | сценарії UC-01…UC-06, барикада вводу, інтерфейси сховищ |
| `src/TaxiDispatch.Infrastructure` | зберігання у файлах JSON і журнал у файл |
| `src/TaxiDispatch.App` | консольне меню й композиційний корінь |
| `tests/TaxiDispatch.Tests` | модульні тести домену й прикладного шару (xUnit) |
| `data/` | умовні дані: 50 місць, 60 водіїв, 80 пасажирів, тарифи, 120 замовлень |
| `docs/` | специфікація, архітектура, посібник, журнал рішень, самооцінка, реєстр боргу |

Архітектура й правило залежностей — `docs/architecture.md`.

## Можливості

Повний опис сценаріїв, правил і таблиць — `docs/spec.md`; як ними користуватися —
`docs/user-guide.md`.

- UC-01 Прийняти замовлення (новий телефон реєструє пасажира).
- UC-02 Призначити водія: найближчий вільний водій потрібного класу в радіусі 5 км.
- UC-03 Виконати поїздку: посадка й завершення з розрахунком вартості.
- UC-04 Скасувати замовлення до початку поїздки.
- UC-05 Знайти замовлення за станом, датою й телефоном.
- UC-06 Звіт «Поїздки за зміну» з підсумками водіїв.

## Тести й покриття

```bash
dotnet test                 # 105 тестів
bash tools/ci-local.sh      # те саме, що конвеєр: формат, стандарт, -warnaserror, поріг 70 %
reportgenerator -reports:coverage/coverage.cobertura.xml -targetdir:coveragereport -reporttypes:Html
```

Покриття вимірюється лише для бібліотек логіки — `TaxiDispatch.Domain` і
`TaxiDispatch.Application` (межа задана в `tests/TaxiDispatch.Tests/TaxiDispatch.Tests.csproj`
і `tests/coverlet.runsettings`). Поточне значення: **96,3 % рядків, 80,7 % гілок**.
Пояснення непокритих гілок — у звіті до СР3 і `docs/self-check.md`.

## Обмеження й відомий борг

Застосунок працює з одним оператором і зберігає дані у файлах JSON, які читаються й пишуться
цілком, тож розрахований на сотні, а не десятки тисяч замовлень. Позиція водія оновлюється
лише після поїздки — відстеження за GPS немає. Відстань рахується по прямій із коефіцієнтом
доріг 1,3, а не за реальним маршрутом. Консольні екрани не мають модульних тестів. Повний
реєстр — `docs/tech-debt.md`.
